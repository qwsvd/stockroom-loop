# Stockroom Loop 中文指南

目标是为一笔订单预留 5 件茶，优先选择最早到期且仍有效的批次。第一次查到 4 件的批次，在实际预留时可能只剩 1 件。程序每一步都把真实数据库结果交还给模型，下一步由模型选择。任务结束时，独立的核验函数逐行检查库存。

## 第一次运行

安装 Git 和 Python 3.11 或更高版本后，在终端运行以下命令。Windows 上如果只有 `py` 命令，可以用它代替 `python`。

```sh
git clone https://github.com/qwsvd/stockroom-loop.git
cd stockroom-loop
git checkout v0.1.0
python -m unittest -v
python replay.py
```

第一条 Python 命令测试程序规则，第二条把真实实验中保存的动作重新放进新数据库，并核对每一步结果。两者都不调用模型。要看模型现场作决定，需要本机已有兼容的 Codex CLI 和 ChatGPT 登录，执行 `python demo.py --policy codex`。每次决策都会使用当前账号的推理额度。也可执行 `python demo.py --policy stdio`，自己输入动作体验同一套环境。

## 用手做一次

输入 `{"op":"inspect"}`。每行依次是批次、商品、到期日、可用量、本单已预留量。试着输入 `{"op":"reserve","lot":"H4","qty":4}`，观察抢先成交的另一笔订单如何使这次请求失败。再次查看库存，根据新数量分两批预留。最后输入 `{"op":"finish"}`。退出码 0 表示全部库存通过核验。可以用 `--steady` 关掉这笔竞争订单，对比相同操作会怎样。

## 源码阅读顺序

1. 打开 [stockroom.py](stockroom.py)，先看四条初始库存，再看 `act` 如何用 SQL 在一次更新里扣减可用量、增加预留量。思考为何失败时不能先扣一部分。
2. 打开 [agent.py](agent.py)，从 `for` 循环跟踪一次“决定、执行、观察”。找到模型声称完成时真正判分的位置。把步数改为 1，预测返回状态。
3. 回到 `verified`，手算一次理想分配。检查它为何还能发现未被订购的肥皂库存遭到意外修改。
4. 打开 [demo.py](demo.py)，找到模型实际收到的文本和它能返回的动作。再打开 [test_agent.py](test_agent.py)，区分脚本决策、模型决策和数据库事实。
5. 对照 [实验记录](docs/experiments.md) 和 [研究依据](docs/design.md)，找出哪个结论来自观察，哪个仍是假设。

## 求职展示与下一项研究

可准确表述为：“我提出了最小智能体研究任务和验收要求。Codex 实现并测试了一个能处理库存变化的实验系统，仓库公开了模型失败、改动和重放记录。”在自己完成复现后，可以另外写明自己的运行环境、发现的问题与改动提交。独立实现、性能提升和真实仓库部署均不属于本次个人经历。

面试练习：如果模型直接回答‘已完成’，谁能证明？如果规则固定，为什么不直接用程序分配？先用自己的话回答，再在源码中指出证据。下一项小实验可以固定任务与步数，只改变数量示例，在多个未见过的库存上记录完成率和调用次数。
